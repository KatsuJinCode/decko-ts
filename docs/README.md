# decko-ts documentation

How the engine is organised is in [ARCHITECTURE.md](../ARCHITECTURE.md), at the
repository root. This directory holds everything else: how parity is verified,
how the engine is deployed on each edge platform, how it is run and operated,
and the decisions that shaped it.

| Document | What it covers |
| --- | --- |
| [parity-method.md](parity-method.md) | How byte parity with Ruby Decko is measured: the oracle, the fixtures its figures were recorded against, what each instrument's comparator normalises, and what a parity figure does and does not tell you. |
| [deploy-bunny.md](deploy-bunny.md) | Deploying on Bunny Edge Scripting against Bunny Database (libSQL): the two bundles, configuration variables, caching switches, the write-surface gate and status endpoints. |
| [deploy-cloudflare.md](deploy-cloudflare.md) | Deploying on Cloudflare Workers over D1: the deploy button, manual deployment, the Worker entry and its bundle, D1's tighter limits and how the engine works within them. |
| [operations.md](operations.md) | Running the engine: local development, the staging server, Server-Timing and the edge profiler, data freshness, cache invalidation, credential rotation and troubleshooting. |
| [TESTING.md](TESTING.md) | What the test suite guards, what data it needs and how to run it. |
| [coverage-inventory.md](coverage-inventory.md) | What the public package measures and what it does not, domain by domain: where each parity figure's evidence lives and what no committed instrument covers. |
| [SECURITY.md](SECURITY.md) | The declared divergences from Ruby that are described: each one carries what Ruby does, what this engine does, why, what it costs, how to configure it and the test that pins it. Two further approved divergences are withheld until a private channel exists to disclose them. |
| [scaling-comparison-deep-nesting.md](scaling-comparison-deep-nesting.md) | Ruby Decko and this engine on the same deep-nesting fixtures, generated by `benchmarks/deep-nesting/build-comparison.mjs` — do not edit by hand, regenerate it. |
| [answers-to-the-earlier-critique.md](answers-to-the-earlier-critique.md) | Point-by-point answers to the third-party critique linked from decko-commons/decko#1282, written from what this repository actually measures. |
| [decisions/README.md](decisions/README.md) | Decision records for the choices that are expensive to reverse. |

`upstream-1282-external-critical-review-fulltext.md` is deliberately not
indexed here: it reproduces third-party text and is excluded from the public
release build, so a link to it would resolve in a repository checkout and 404 in
the published package. `answers-to-the-earlier-critique.md` answers the same
critique by its own numbering, without reproducing it.

## Conventions

Documents use relative links, so they resolve from the repository root on
GitHub and in an editor. Anything under `benchmarks/` is a
regenerable artifact rather than a source of truth; a document that cites one
cites it as evidence, not as a place to edit.
