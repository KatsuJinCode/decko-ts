# Editor settle diagnostic and actual replay

The complete production run at f0c91b5a passed all six journeys, but the rich fill step spent 30.465s waiting. Investigation found `settle()` tested optional TinyMCE statusbar path items and passed `{timeout:8000}` as the browser function argument, leaving Playwright's default 30s timeout. A statusbar breadcrumb is selection-dependent and may be disabled; it does not establish editor initialization. TinyMCE's [Editor API](https://www.tiny.cloud/docs/tinymce/latest/apis/tinymce.editor/) documents the editable body and initialization lifecycle.

Commit 6620679f waits for every rich textarea's actual editor to be initialized and have an editable body, using the correct timeout argument. Failed editor readiness now fails the step. Controls in a real headless browser verify plain inputs need no rich editor, missing initialization fails, and an initialized editor without statusbar breadcrumbs succeeds. The separate missing-public-provider host control also passes (2 tests, 3.134s total).

Actual production host replay from clean 6620679f, with the same fixture, journey definitions, stable gem-public provider and verified shared LibSass binary, completed Date persistence in **43.843s** and rich persistence in **36.269s**. The rich fill step fell from **30.465s to 0.472s**; startup and network time varied, so aggregate duration is not an isolated speed benchmark. Both journeys still asserted persisted values after fresh browser sessions and actual owned-host restarts.
