# The one-trip page payload — deployment config for the operator

**Lane:** lane-one-trip-serve-2026-10-04 · **Tip at writing:** lane-one-trip-serve-2026-10-04
(6f35429a deploy-union-final + lane commits) · **Measured proof:**
`benchmarks/one-trip-render/one-trip-serving-line-posture-report.json` (regenerated by
`benchmarks/one-trip-render/run-one-trip-serving-line-off-on-proof.mjs`).

The one-trip payload is OFF by default. Setting the two env vars below turns it on; nothing
else in the request path changes (render-gate.ts: every failure mode falls back inert to the
unchanged path — the payload is an optimization, never a correctness dependency).

## Env vars and values

| Var | Value | Meaning |
|---|---|---|
| `DECKO_ONE_TRIP` | `1` | Arms the gate (render-gate.ts `oneTripWantsPayload()`). Any other value / absent = OFF, the deployed default byte-for-byte. |
| `DECKO_ONE_TRIP_STORE` | absolute path to the built store file | The precompute side store (closure-builder). REQUIRED when the gate is armed; without it the payload is inert with a once-only warn (render-gate.ts). |

## The boot requirement (landed this lane)

When the gate is armed, the serving boot MUST raise the Temporary-cache reset threshold:
`bootCorpusDeckEngines(driver, { maxTemporaryCacheKeys: 200_000 })` — wired into the union
handler's `bootDeck` (bunny-edge-engine-handler.ts) via
`ONE_TRIP_BOOT_MAX_TEMPORARY_CACHE_KEYS` (bunny-edge-deck-boot.ts), ON only. Unarmed boots are
byte-for-byte the previous default.

Why it is not optional: the Ruby-parity default is 10,000 keys
(src/card/fetch/cache.ts `DEFAULT_MAX_TEMPORARY_CACHE_KEYS`), and seating one page payload
writes ~3.5k keys. At the default cap a multi-page session crosses it mid-session and the
wholesale reset evicts primed state — MEASURED on the serving line at the default cap: ON cold
EXCEEDED OFF cold on Aikido (+77 round trips), About (+266) and Eagle (+7); with the raised
cap ON cold dropped below OFF on all 5 probe pages (see the proof report). The module fixture
recorded the same class earlier: 1,668 seating-induced re-queries on Eagle at the default cap,
0 with the cap raised (tests/card/one-trip/one-trip-fixture.ts).

## The store is a PRECOMPUTE artifact

Built by `buildOneTripClosure({ corpus, side, pageNames })` (src/card/one-trip/closure-builder.ts)
from the serving corpus into a separate store file. Never built at render time (render-gate.ts's
contract). Measured build on the 19,482-card trial mirror: ~4.8-9 s (lane runs: 4,674 / 9,023 /
4,772 ms) for the 5 probe pages; 73,408 edges. The serving side only READS the store (A2: the
derived store is read-scope for serving; invalidation.ts owns the write-time recompute
protocol, not consulted by the render path).

Rebuild cadence: the store is a build-time snapshot of derived data (closures, rule candidates,
write-time search results). On a READ-ONLY serving deck it stays valid. On a deck that accepts
writes, content changes make the store stale for affected pages — the payload seats rows into
the fetch cache, and the render's own execution stays authoritative, so a stale row costs a
residue re-ask, not wrong bytes (row-set contract, one-trip-fetch.ts header + byte-identity
pin); the write-time invalidation protocol is the designed follow-up (invalidation.ts), not
part of this config.

## Serving shapes — what is proven where

1. **Node/local serving (LocalSqliteDriver, side-store FILE): FULLY PROVEN.** The real
   serving-line handler (bunny-edge-engine-handler.ts) behind node:http, Hrana seam over the
   trial mirror: 5/5 probe pages byte-identical OFF vs ON (modulo the engine's own per-render
   SecureRandom slot ids), data fetch = 1 round trip per page, cold ON < cold OFF and warm
   ON <= warm OFF on every page (proof report). This is the vm-staging-server.mjs-class host
   shape.

2. **Edge serving over Bunny Database (BunnyDbDriver, Hrana v2): the payload seam is the
   named remainder.** `attachDerivedStore` issues `ATTACH DATABASE '<path>' AS one_trip`
   through the driver. A local sqlite connection honors it (proven); whether the PRODUCTION
   Bunny Database service accepts ATTACH of a side file was NOT probed — this lane is under a
   ZERO live requests rule (house rules for serve-speed lanes), and an edge isolate has no
   filesystem path to attach anyway. The designed production shape per the module's own seam
   note (one-trip-fetch.ts:27-32): materialize the derived tables INTO the serving database —
   "drops the prefix and the ATTACH call; nothing else changes" (`DERIVED_STORE_ATTACH`
   seam). That materialization is NOT wired yet; until it is, the honest edge deployment
   posture is OFF (the default).

## Hops law placement

The law's absolute clauses (cold <= 14, warm <= 1) are FIXTURE-scoped:
`tests/card/render/hops-per-render-one-page-law.test.ts` pins them on its fixture (green),
and `tests/card/one-trip/hops-gate-one-trip-posture.test.ts` pins the same law with the gate
armed (green). On the 19,482-card corpus the absolute clauses hold in NEITHER posture (OFF
cold reaches 6,721 wire round trips on /Aikido; OFF warm 23/4/2) — the serving-line gate this
lane records is comparative (ON never costs more than OFF at the same boundary) and held 5/5.
