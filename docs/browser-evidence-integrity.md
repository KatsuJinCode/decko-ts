# Journey evidence integrity repair

The old comparator could return zero after failed comparisons, omitted missing reference/extra actual journeys, silently overwrote duplicate IDs and observations, and accepted matching reference HTTP500 pages. It had no binding to a candidate, build artifact, fixture or journey definition. Historical51counts in docs/browser-journeys.md are explicitly old parity evidence, not site acceptance.

The comparator now needs exact full `--candidate <sha>` and verifies the complete journey definition (or an explicitly diagnostic partial selection), result IDs, step/outcome sequence, observation labels, complete execution, successful non-server-error page observations, fixture/journey SHA256, clean source commit, run identity, browser/runtime versions, canonical Ruby3.3 reference runtime, and actual build receipt linking source+diff to the exact dist tree. Missing/extra/duplicate/mixed/stale evidence and any comparison failure exit1. Zero-selection also fails. It does not normalize new differences away. Report `productionAcceptance` stays false: isolated host comparison is separate from deployed-site acceptance.

`run-journeys` records those identifiers and actual runtime endpoint/browser versions. `run-all` shares a runID across shards, preserves a failure report/summary and exits nonzero. The production Node engine profile explicitly uses PBKDF2, leaves asset-refresh at host default, and records whether an SCSS compiler was configured. The parity profile retains its explicit Ruby-compatible legacySHA1/never settings.

`npm run build:engine` now compiles source and copies the complete checked-in vendor runtime tree (snapshots, LibSass WASMJS module, Uglifier modules and license/provenance files). It imports the actual static snapshot/compiler consumers before issuing `.runtime/browser-build.json`. This repairs the missing dist/vendor runtime files exposed by actual entry boot. Compiler binaries remain separately verified native cache artifacts, passed through the host's documented DECKO_SASSC configuration.

Verification:13 CLI controls include real nonzero missing/extra/duplicate, matchingHTTP500, dirty/wrong source, missing provenance, stale build, incomplete steps/observations, wrongRuby and ordinary comparison differences; valid complete bound evidence exits0. Typecheck passes. This verification is comparator behavior, not browser acceptance.

Initial actual production-profile browser diagnostics captured signin/signout and wrong-password journey failures because first-page asset refresh had no configured compiler; serverlogs name the error. That owned run tree was stopped after two failures rather than repeating51identical timeouts. Its source was dirty and artifact came from an earlier build; it is retained only as a diagnostic. The next run rebuilds the exact committed tree with the verified shared LibSass cache and explicit production profile. Existing Ruby3.4 raw reference at the separate journey checkout is preserved; no Ruby3.3 claim can be attached retroactively.
